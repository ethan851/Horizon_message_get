In May 2025, China's first domestically developed ArF immersion lithography machine, built by He Rongming's team, was delivered to SMIC. It can support 7nm chip production using multi-patterning techniques, breaking the foreign monopoly on high-end lithography equipment. This breakthrough significantly reduces China's dependence on foreign lithography equipment, which is critical for semiconductor self-sufficiency. It also enhances China's competitiveness in advanced chip manufacturing and has major geopolitical implications. The machine uses argon fluoride (ArF) excimer laser with 193nm wavelength and immersion technology to improve resolution. Combined with multiple patterning, it can achieve 7nm node features, though at higher cost and complexity compared to single-exposure extreme ultraviolet (EUV) lithography.

**Background**: ArF immersion lithography is a photolithography technique that uses a liquid (typically water) between the lens and the wafer to increase numerical aperture and enable finer patterns. It has been the workhorse for manufacturing 45nm to 7nm nodes, often combined with multiple patterning to push beyond its conventional limit. The team, based in Shanghai Zhangjiang, has over 80% domestic market share in advanced packaging lithography and 33% globally.

## [Debate on JWT Security Flaws and Use Cases](https://gist.github.com/samsch/0d1f3d3b4745d778f78b230cf6061452) ⭐️ 8.0/10

A controversial post arguing against JWTs sparks a nuanced debate about their security flaws and appropriate use cases, with comments defending their use for service-to-service communication and short-lived tokens. The discussion highlights critical considerations for authentication design in web development, particularly the trade-offs between session-based and token-based approaches, and influences how developers choose auth strategies. The original post criticizes JWTs for issues like lack of revocation and reliance on secret keys, while commenters point out that proper short-lived tokens and revocation lists can mitigate risks, and that JWTs are well-suited for service-to-service OAuth2 flows.

hackernews · dzonga · Jun 16, 16:49 · [Discussion](https://news.ycombinator.com/item?id=48558147)

**Background**: JSON Web Tokens (JWT) are a compact, URL-safe means of representing claims between parties, commonly used for authentication and authorization in web applications. They can be signed using a secret or a public/private key pair, but once issued, they are valid until expiry unless a revocation mechanism is in place. Session-based authentication, on the other hand, stores session data server-side and can be invalidated immediately.

**Discussion**: Commenters generally agree that JWTs have flaws for browser-based user sessions but defend their use in service-to-service communication. Some note that revocation can be handled with short-lived tokens and nonce checks, and that the standard is secure when implemented correctly.

This case sets a legal precedent clarifying that platforms have a 'gatekeeper' duty to take proactive measures like account suspension against repeat infringers, beyond merely removing infringing content. The platform removed infringing content each time after over 20 complaints but never suspended the user, leading to continuous re-uploads. The court identified this as contributory infringement because the platform had the capability to take stronger action but failed to do so.

## [Critical Path Traversal in Nezha Monitoring (CVE-2026-53519)](https://t.me/zaihuapd/42001) ⭐️ 8.0/10

A critical unauthenticated path traversal vulnerability (CVE-2026-53519, CVSS 9.1) has been disclosed in Nezha monitoring versions below v2.0.13, allowing remote attackers to read arbitrary files such as config.yaml and extract JWT secrets via a crafted GET request. This vulnerability is critical because Nezha is a widely used open-source server monitoring tool, and exploitation could allow attackers to forge JWT tokens, gain unauthorized administrative access, and compromise the entire monitoring infrastructure. The issue stems from insufficient input validation in the dashboard route, allowing path traversal sequences (../). Immediately affected are all deployments running Nezha v2.0.12 or earlier; no authentication is required to exploit the vulnerability.

telegram · zaihuapd · Jun 17, 01:25

**Background**: A path traversal (or directory traversal) attack exploits insufficient sanitization of user-supplied file names to access files outside the intended root directory. JSON Web Tokens (JWT) are often used for authentication; the JWT secret is a symmetric key used to sign and verify tokens. If an attacker obtains the secret, they can forge valid tokens and impersonate any user.
